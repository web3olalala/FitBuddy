# 今天练了吗 · 产品需求文档（PRD）

- 版本：V1.2 健身成就
- 更新日期：2026-10-17
- 产品形态：手机优先、兼顾桌面的 PWA 网页 App
- 本文保留产品规则与原验收标准；当前运行方法见 [README](../README.md)，本次验证结果见 [验证记录](./VERIFICATION.md)。

## 1. 产品目标

为个人提供一个简洁、容易坚持使用的健身记录工具：安排每周训练部位与动作清单，确认计划后开始训练，在温和陪伴中记录每个动作的每一组，通过历史记录和图表了解自己的变化。

第一版应让用户在没有账号、没有网络连接的情况下，完成日常记录。数据保存在当前设备，正常关闭、刷新和重新打开后可继续使用。

### 1.1 目标用户与成功标准

- 主要用户：产品所有者本人，有按周安排训练、记录重量与次数、观察体重变化的需求。
- 能从首页直接开始或继续训练，不必先填写完整个人资料。
- 能在手机上快速记录每组数据，训练中断后找回已保存内容。
- 能补录、修改和删除历史训练，统计随之正确更新。
- 能导出完整备份，并在另一个支持的设备上恢复。
- 以本文的验收用例作为第一版完成标准，不以页面数量或视觉演示代替功能完成。

### 1.2 主要使用场景

| 场景 | 用户操作 | 预期结果 |
| --- | --- | --- |
| 安排一周训练 | 给周一安排胸与卧推动作、周三安排背与划船动作，其他日期按需设置 | 每周重复显示，可随时修改 |
| 边练边记 | 记录页确认今日计划、调整动作后开始；逐组填写并打卡 | 输入自动保存，有轮换鼓励与完成庆祝 |
| 训练被打断 | 返回首页、切换应用或关闭后重新打开 | 找到原草稿并继续，不生成重复训练 |
| 练完后补记 | 从记录页选择过去的日期，录入训练 | 完成后进入对应日期的历史和统计 |
| 查看进步 | 选择时间范围与动作 | 查看训练次数、负重或次数变化、体重趋势 |
| 更换设备 | 在原设备导出，在新设备导入 | 恢复计划、记录、草稿、目标及自定义动作 |

## 2. 范围与产品规则

### 2.1 已确认的产品方向

- 四个模块：训练计划、运动记录、进步统计、个人设置。
- 周计划保存训练部位与动作清单；训练前在记录中确认或临时修改，修改只影响本次训练。计划暂不预设组数和重量。
- 训练按每一组分别记录重量和次数。
- 内置常用动作，同时支持自定义添加动作。
- 同时支持每周训练次数目标与目标体重。
- 支持边练边记、草稿续写以及事后补录。
- 兼顾 iPhone、安卓与电脑，第一版采用 PWA。
- 本地存储，提供手动备份和恢复，不做云同步。
- 视觉参考苹果健康 App 的简洁、清晰与舒适感，不直接照搬。

### 2.2 为开发补齐的执行规则

以下为本版建议采用的具体规则，随本文一起评审；不代表已实现。

| 项目 | 第一版规则 |
| --- | --- |
| 周的定义 | 周一至周日，按设备本地日历日期计算 |
| 日期保存 | 训练日期、体重日期使用日历日期，不因 UTC 转换而偏移一天；创建和修改时间另行保存 |
| 计数口径 | 一份已完成训练计一次，同一天可以有多次；草稿不计入 |
| 训练日期 | 新训练默认今天，补录与修改只能选择今天或过去的日期 |
| 单位 | 负重、体重使用 kg；体脂率使用 %，腰围使用 cm；不做单位切换 |
| 数值 | 负重为大于等于 0 的有限数，可有小数；次数为正整数；体重和目标体重为大于 0 的有限数 |
| 自重动作 | 可不填写负重，空白表示未记录外加负重，与填写 0 保持区分 |
| 草稿数量 | 同时最多一份未完成训练，补录中的未完成训练也算草稿 |
| 身体指标频率 | 每个日期一条测量记录，可独立填写体重、体脂率和腰围；至少一项，同日再次填写需提示更新 |
| 目标 | 两种目标均可暂不设置；每周次数为正整数，达标后仍可继续记录 |
| 恢复方式 | 校验、预览并确认后完整替换，不合并，不自动去重导入 |
| 有氧范围 | 可作为计划标签；第一版训练数据按组、重量、次数记录，不增加时长、距离、配速等专用字段 |

### 3.2 导航行为

- 手机底部四个入口固定为「计划、记录、进步、我的」，图标配文字，选中态清楚。
- 默认进入计划页；首次使用不强制填写目标、不预置用户训练记录。
- 训练编辑作为独立页面，隐藏底部导航，提供返回入口与底部主要操作。
- 从动作选择页返回后保留当前训练内容和输入上下文。
- 系统或浏览器返回操作与页面返回保持一致，不能因返回丢失已保存草稿。
- 电脑端使用左侧导航，主内容限制宽度，适当并排展示卡片；训练录入保持单列。

## 4. 视觉设计与交互要求

### 4.1 视觉方向

- 白色卡片为主，浅灰绿色页面背景；青柠绿强调选中日期、导航和训练入口，炭黑用于今日训练和成就摘要。图表使用同系列绿，保留明确文字对比。
- 使用系统字体，形成页面标题、卡片标题、关键数字、正文、辅助说明的明确层级。
- 使用圆角卡片、适度留白、轻边框或轻阴影；避免厚重阴影、大面积渐变和装饰性动效。
- 图表保持简洁，轴标签、单位、时间范围可读；点击数据点能查看具体值。
- 不依靠绿色或红色单独表达状态，同时提供文字或图标。
- 空状态是真实无数据状态，不填充示例成绩或虚构曲线。
- 2026-10-17 确认的界面优化：融合参考图的平面色块、圆角和数字层级；保留现有系统字体、图标与功能入口，不复制参考图的装饰插画或手机外框。
- 手机计划页优先显示未来七天与当日训练，然后显示紧凑周目标；身体指标使用并排数值卡片，成就在常用手机宽度双列、小于 360 像素时单列、1100 像素起三列。
- 页面切换采用 180ms 淡入，按钮反馈约 150ms；系统开启减少动态效果时关闭这些动效。训练输入保持浅色与至少 16px 字号，输入时不重新构建页面。

### 4.2 手机适配与可访问性

- 以 375–430 CSS 像素手机宽度优先设计，至少检查 320、390、430、768、1280 像素宽度。
- 页面无非必要横向滚动，文字和输入框不重叠；主要触控区域不小于 44 × 44 CSS 像素。
- 兼顾手机安全区域、底部手势区域和软键盘，当前输入与主要操作可滚动到可见位置。
- 重量使用小数输入键盘，次数使用整数输入键盘；仍需验证实际输入，不能仅依赖键盘限制。
- 表单有可识别标签、明确错误信息、键盘焦点；弹窗关闭后焦点回到合理位置。
- 返回、删除、导入等操作有明确反馈；保存失败不能显示为保存成功。

## 5. 模块功能与操作流程

### 5.1 训练计划

**页面内容**：当前日期、本周目标完成情况、从今天起连续七天（含今天）的日期条、所选日期计划卡片、按相同日期顺序排列的安排列表。移动目标日期也使用此范围，跨周、跨月、跨年连续显示；每周重复规则及自然周统计口径不变。

**功能要求**：

1. 可为周一至周日添加和修改一个或多个部位，至少提供胸、背、腿、肩、手臂、核心、有氧及自定义内容。
2. 明确区分「未安排」「休息日」「已安排训练」；休息日与训练部位互斥。
3. 可清除某日安排，恢复为未安排。
4. 计划按周重复；保存动作标识清单，可选择内置、已有自定义动作，或在计划弹窗新建动作；取消弹窗不保存新动作。修改计划不覆盖已有动作、训练数据或历史；当天尚未开始且尚无动作的空草稿自动接入计划（手动清空过的除外）。
5. 首页或记录页可进入今日训练确认，自动带入今天的计划；首页选择其他星期时明确提示开始入口仍用于今天。未安排或休息日也允许自由添加；已有草稿则优先继续。
6. 未设次数目标时显示实际训练次数及设置入口；超过目标时显示真实次数，不截断计数。

**操作流程**：计划页 → 选择星期 → 编辑安排 → 选择部位和动作或设为休息 → 保存 → 周视图与记录页今日预览更新。

### 5.2 动作选择与自定义动作

1. 提供覆盖常见部位的基础动作，例如卧推、俯卧撑、划船、引体向上、深蹲、肩推、弯举、卷腹。
2. 支持按名称搜索和部位筛选，内置、自定义动作都可找到。
3. 自定义动作至少填写名称、所属部位、是否需要填写负重。
4. 名称去掉首尾空格后不能为空；遇到同名动作提示选择已有动作，避免无意重复创建。
5. 选择后加入训练并显示第一组输入；训练数据保留动作标识和名称快照，使历史数据可读。
6. 第一版只要求添加自定义动作，不扩展动作库批量管理、视频教程或动作教学。

**操作流程**：训练编辑 → 添加动作 → 搜索或筛选 → 选择动作 → 返回训练；无匹配时 → 创建自定义动作 → 加入训练。

### 5.3 新建、继续与完成训练

1. 新建默认今天，以当天计划动作生成独立草稿，先进入准备状态。用户可增减动作和组数、提前填写预期数值，再点「确认并开始训练」。至少一个动作才能开始，训练时可继续修改。补录先选日期，直接录入，不启用实时陪练。
2. 每个动作包含若干组，组号按顺序显示；每组单独填写重量、次数。
3. 添加下一组沿用上一组数值，用户可修改；可删除一组或移除动作，短暂提供撤销入口。
4. 有效输入与结构变更自动写入本地，显示「保存中／已保存／保存失败」。正在输入的空值允许保留在草稿中，非法数值需提示，不能被标记为已完成。
5. 不把应用关闭时的最后一次回调作为唯一保存时机；已显示保存成功的数据重新打开后必须存在。
6. 同时最多一份草稿。再次开始或补录时，可继续原草稿，或确认放弃后新建；不得默默覆盖。
7. 点击完成时，至少存在一个动作，每个保留动作至少有一组，各组次数有效，需负重动作的重量有效。未填写的多余组须补全或由用户删除。
8. 校验失败定位到具体输入；校验通过且本地写入成功后，才切换为已完成并进入详情页。
9. 连续点击完成不能生成重复记录；完成后本周次数、历史列表及图表立即更新。
10. 训练中每 20 秒轮换温和鼓励，页面隐藏或弹窗打开时暂停换句；可手动换一句或收起，不使用声音或强制提醒。收起时不重建输入区域。
11. 逐组打卡前检查实际次数及必填重量；打卡状态本地保存，修改数据会撤回该组打卡。打卡只表示组进度，整次仍须点击完成。点击「完成训练」表示确认全部填写的组均已完成，不要求重复点击每个打卡圆圈。
12. 完成写入成功后显示轻量庆祝动画、小绿花及真实动作数、组数和本周训练次数，提供查看进步入口。尊重减少动态效果设置；历史编辑和补录不播放实时训练庆祝。

**操作流程**：记录 → 查看今日计划 → 确认或临时调整 → 确认并开始训练 → 陪练鼓励与逐组打卡 → 自动保存 → 完成校验 → 写入成功 → 庆祝与训练详情。补录与历史修改保留直接编辑流程。

### 5.4 历史记录与编辑删除

1. 按训练日期倒序展示，提供月份切换；同日期可显示多份训练。
2. 卡片展示日期、动作名称摘要、动作数量、总组数，草稿独立置顶。
3. 详情展示全部动作和各组数值，空负重按自重或未记录负重表达，不能显示无效数值。
4. 历史编辑使用独立编辑副本，明确提供「保存修改」与「取消」。编辑过程不立即改写原记录。
5. 返回时若存在未保存修改，提示继续编辑或放弃；关闭后重新打开至少保留原已完成记录，不承诺保留历史编辑的临时副本。
6. 保存修改采用完成训练相同的校验，成功后更新统计；改日期后移至对应月份和周。
7. 删除整次训练须展示日期、摘要并确认；取消无变更。删除成功后更新相关统计，不改变周计划。

**操作流程**：记录列表 → 训练详情 → 编辑 → 保存修改或取消；删除 → 核对摘要 → 确认 → 返回记录列表。

### 5.5 进步统计

**时间范围**：近 4 周、近 12 周、全部。近 N 周指包含本周的 N 个自然周，从首周周一至今天；所有图表使用同一时间范围。

| 图表 | 数据与口径 | 操作 |
| --- | --- | --- |
| 训练频率 | 每周已完成训练份数，缺少训练的周显示 0；设置目标后显示当前每周目标线 | 点击柱可看次数并进入对应周的记录列表 |
| 动作进步 | 按动作标识汇总；需负重动作每次取有效组的最大重量，同时展示达到该重量的各组次数；自重动作采用单组最高次数，标题明确指标 | 选择动作、点选数据查看日期与数值，进入对应训练详情 |
| 体重趋势 | 按日展示已记录体重；有目标时显示目标线 | 点击数据点查看日期和体重，进入记录管理 |

- 所有训练统计排除草稿；同一次训练重复添加同一动作时，汇总其全部组后取指标。
- 修改或删除训练后重新计算，不保留失效的缓存结果。
- 自重次数图不混用重量轴；可记录的额外负重仍可在训练详情中查看。
- 一个数据点展示单点；无数据展示引导；体重未记录的日期不补 0，不宣称插值为真实测量。
- 负重上升只代表该指标变化，不直接给出医学或训练效果判断。
- 目标线使用当前设置，修改目标会更新图表；第一版不追踪目标变更历史。

### 5.6 身体指标与个人目标

1. 从我的页记录体重、体脂率、腰围，进步页保留体重入口，统一进入身体指标表单。默认今天，可选过去日期；支持修改和删除。至少填写一项，体重和腰围须为正有限数，体脂率须大于 0 且小于 100。不自动推算或做健康诊断。
2. 同日只能一条身体指标记录。新增表单切换日期会带入该日原值；再次填写或修改日期冲突时确认替换或取消。提示留空项目会被清除；删除确认针对该日全部指标。
3. 删除需确认；操作成功后更新体重曲线和最新体重。
4. 我的页面支持设置、修改、清除每周次数目标和目标体重。
5. 我的页各指标分别取有实测值的最新日期，并标出各自测量日期。只记体脂率或腰围不覆盖旧体重，也不进入体重曲线；目标不生成实测数据。
6. 用户可以只设置一种目标或全部暂不设置，不影响其他功能。

## 6. 数据保存、导出与恢复

### 6.1 本地保存要求

- 业务数据以 IndexedDB 为唯一持久化来源；应用静态资源离线缓存与用户数据分开管理。
- 所有计划、动作、草稿及逐组进度、完成记录、身体指标和目标均在当前设备本地保存，不上传业务服务器或第三方分析服务。
- 页面刷新、关闭重开、正常离线重开后，读取并展示最近一次成功保存的内容。
- 写入成功状态以数据库事务完成为准；写入失败明确提示并保留当前界面输入，提供重试，不能悄悄回退为空数据。
- 数据库打开失败或已有数据读取异常时展示恢复或重试提示，不能以“初始化”为由覆盖原数据。
- 保存顺序应可预测，较早写入不能覆盖较新的输入；恢复期间禁止发起冲突写入。
- 多页面或多个标签页打开时，不允许旧页面把较新版本的整份数据覆盖；最低限度采用修订检查并提示刷新，不要求实时多端协作。
- 正常应用更新不清空用户数据库；涉及格式升级时保留旧数据，失败不能破坏原数据。

### 6.2 必须保存的数据

下表描述逻辑数据，不强制每行对应一张数据库表。

| 数据 | 最少包含内容 |
| --- | --- |
| 文档元数据 | 数据格式版本、数据修订标识 |
| 周计划 | 星期、未安排／休息／训练状态、部位或自定义内容、动作标识清单 |
| 目标 | 每周次数、目标体重，允许未设置 |
| 自定义动作 | 稳定标识、名称、部位、是否需要负重 |
| 训练记录 | 稳定标识、训练日期、草稿／已完成状态、准备／训练阶段、实时／补录模式、开始时间、计划部位快照、创建与修改时间、有序动作列表 |
| 训练中的动作 | 条目标识、动作标识、名称与记录类型快照、有序组列表 |
| 每组数据 | 组标识、重量、次数、打卡状态，草稿允许未填完 |
| 身体指标记录 | 稳定标识、测量日期、体重／体脂率／腰围（未测为 null）、创建与修改时间 |

数据与备份格式升级为版本 2，导入支持版本 1、2。旧数据先完整校验，再补充新字段，最后原子写入；旧草稿继续处于训练状态，旧体重不变，新增指标为空。升级失败保留原数据。

内置动作标识应保持稳定。恢复时应保证历史动作名称及记录类型可读，不因动作库版本变化丢失历史信息。

### 6.3 导出备份

1. 从我的页面手动导出 JSON 文件，文件名包含产品名称、日期及时间，便于区分多次备份。
2. 文件包含产品标识、备份格式版本、导出时间和完整业务数据，包括未完成草稿、自定义动作与目标。
3. 导出取自已成功保存的一致数据快照；存在失败或未完成写入时先提示处理，不将尚未保存内容误报为已备份。
4. 无任何训练数据时也能导出有效备份，以保存计划和目标。
5. 使用平台支持的文件下载或保存流程；不能仅弹出“成功”而没有实际可保存的文件，也不能声称知道用户是否已在系统界面保存文件。
6. 备份为未加密 JSON，可包含个人训练与体重信息，用户自行选择文件保存位置。

### 6.4 恢复备份

1. 选择文件后先完整解析和校验，校验完成前不写数据库。
2. 校验产品标识、版本、必需字段、类型、有效日期、数值、标识唯一性、关联关系以及最多一份草稿等约束。
3. 拒绝损坏 JSON、不兼容版本、错误数据结构及不符合业务约束的数据，说明原因并保留现有数据。
4. 预览显示导出时间、已完成训练数量、草稿数量、体重记录数量及自定义动作数量。
5. 明确说明将替换当前数据，提供取消、先导出当前备份、确认恢复三个操作。导出后仍需用户明确确认恢复。
6. 确认后通过原子事务完整替换：要么全部成功，要么保留原数据；禁止先清空后分批写入。
7. 恢复失败展示原因和重试入口；恢复成功后更新所有模块，不保留旧界面统计。
8. 第一版不支持合并导入、部分恢复、导入其他健身 App 格式或未知未来版本。

### 6.5 存储边界与 PWA 要求

- 应用采用 Manifest 提供名称、图标、主题色与独立窗口配置；提供适合 iPhone、安卓的安装说明，不假定所有浏览器都有相同安装按钮。[MDN：PWA 安装条件](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)
- 首次打开需要加载应用资源；资源缓存完成后应支持离线重开并使用四个模块。Service Worker 运行需要安全上下文，正式手机访问采用 HTTPS，本机开发可使用 localhost。[MDN：Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API)
- IndexedDB 适合本地结构化数据和事务操作；数据受来源隔离，域名、协议或端口变更后不能假定读取原来源的数据。不同设备、浏览器或安装环境之间不承诺自动共享数据。[MDN：IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)
- 正常关闭与重开应保留已保存数据，但不能承诺在清除网站数据、设备重置、系统或浏览器回收存储之后仍永不丢失。可在支持时申请持久化存储，但其成功不替代备份。[MDN：存储配额与回收](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)
- 本地开发阶段不能把电脑 localhost 链接当成手机部署地址。第一版需要具备 PWA 能力，正式托管与手机部署另行确认。

## 11. 健身成就系统（2026-10-17）

### 功能与口径

- 在「我的」和「进步」提供成就页入口，保留四个主导航。独立页面展示已解锁、待解锁、解锁日期、累计次数进度及动作当前历史最高重量，使用现有白绿圆角卡片风格。
- 累计 10 次解锁「十次，起步成章」，累计 30 次解锁「三十次，坚持有形」。以已完成训练份数计数，补录计入，草稿不计入。
- 每个内置或自定义负重动作各有一枚「突破自己」徽章。按训练日期、同日创建时间排序；两者完全相同时按稳定记录 ID 排序。同一次训练中的同一动作先汇总全部组取最高重量。首次已完成记录建立基准，在之后的已完成训练中严格超过此前最高重量才解锁；追平、同次加重不解锁，自重动作不生成重量徽章。后续刷新纪录更新最高值，不重复发放同一徽章。
- 解锁日期取仍存在的记录中首次满足条件的训练日期。历史修改、删除、补录、备份恢复后自动重新计算；不再满足条件时恢复未解锁状态。成就不独立存储，不新增数据库字段、不改变 v2 备份格式，现有历史数据直接适用。
- 完成训练（含补录）成功保存后，只为本次新解锁的徽章显示轻量渐入提示，可关闭或进入成就页。保存失败不显示成功提示；历史编辑、恢复备份、刷新和再次访问详情不重复播放。尊重减少动态效果设置，不增加声音或推送。

### 验收

| 编号 | 条件 | 必须结果 |
| --- | --- | --- |
| AC-31 | 累计 9／10／29／30 次；加入草稿；删除第 10 或第 30 次 | 门槛准确，草稿排除，删除后重算，解锁日期与真实记录一致 |
| AC-32 | 首次记录、同次多组和重复动作、追平、跨次加重；自定义与自重动作 | 只在跨次严格突破时解锁对应负重动作徽章；动作互不干扰 |
| AC-33 | 打开两处入口、刷新、离线重开、恢复现有格式备份 | 已解锁和待解锁展示正确，数据不改变，成就一致 |
| AC-34 | 一次解锁多个、保存事务中止后重试、关闭／重开、减少动态效果 | 只在写入成功后展示新徽章，失败不误报，关闭刷新不重播，减少动态效果关闭动画 |
| AC-35 | 编辑重量、删除训练、补录早期记录 | 以当前完整历史重新计算，最高重量和徽章状态同步，不影响原统计口径 |
